# 06 · 学习路径

> **学习目标**
> 完成本节后，你应该能够：
> 1. 判断自己是否具备开始学习的前置条件；
> 2. 按顺序走完七个阶段（阶段 0–6），每个阶段都有**可观察的完成判据**；
> 3. 针对自己的真实场景，选出下一步该深入的方向。

### 证据标签约定

`【Source-derived · Sxx】` 来自根文档 `source-sglang.md`；`【Research-derived · Rxx】` 来自外部权威来源；`【Illustrative】` 为教学性构造，不主张 SGLang 的未经验证行为。完整定位码与出处见 [07 · 验证记录](07-verification-record.md)。

## 6.1 前置知识清单

进入学习路径前，先自检。**不满足"必备"项就别硬上**——这份方案里很多困惑其实是前置知识的缺口。

### 必备（缺了会卡在阶段 4）

| 需要 | 为什么 | 自检问题 |
|---|---|---|
| **Linux + NVIDIA GPU 环境** | 全部操作都是 Linux 命令行 | 你能 SSH 到有 GPU 的机器吗？`nvidia-smi` 有输出吗？ |
| **容器基础**（若用容器部署） | 共享内存需要显式设置【S16】 | 你知道 `--shm-size` 是干什么的吗？【S16】 |
| **Python 环境隔离** | SGLang 以 Python 模块方式启动【S18】 | 你能用 `venv`/`conda` 建隔离环境吗？ |
| **模型权重的访问权限** | 模型需要下载到本地 | 你拿到模型许可了吗？（部分模型需要额外授权） |

### 强烈建议（缺了会卡在阶段 2）

| 需要 | 为什么 |
|---|---|
| **张量并行 / 流水线并行 / 数据并行的区别** | 理解"张量并行（TP）绝对不能跨节点或跨PCIe Switch边界"这条铁律【S2】【S4】 |
| **显存与 KV Cache 的基本直觉** | 理解"精度决定装不装得下"这条链【S11】【S15】 |
| **量化格式的基本概念**（BF16 / FP8 / FP4） | 理解 NVFP4 的取舍【S11】【S13】 |
| **PCIe 拓扑与 NUMA** | 读懂 `nvidia-smi topo -m` 的输出 |
| **CUDA 基础**（不需要会写 kernel） | 理解 SM_120、CUDA 版本、后端选择【S12】【R31】【R32】 |

### 可选

| 需要 | 用于 |
|---|---|
| **Kubernetes** | 理解 KServe / K8s 编排这一层 |
| **Ray** | 理解 Ray Serve 作为上层编排【S24】 |
| **分布式训练背景** | 理解"张量并行在训练里也是同样的通信模式" |

> **没有 GPU 也能学完阶段 0–2 的概念部分**。[01](01-positioning-and-background.md)、[02](02-core-concepts.md)、[03](03-core-functionality.md) 全部是概念性的；[05](05-related-tools.md) 的选型部分同样不需要动手。只有阶段 4 之后需要真实环境。

## 6.2 七阶段学习路径

每个阶段都遵循同一个结构：**读 → 练 → 判据**。"判据"必须是**可观察的**（能跑出一条命令、能说出一句话、能做出一个决定），不是"理解了"。

---

### 阶段 0 · 确认环境（前置）

**读** → [04 · 4.0 开工前：确认三件事](04-usage.md#40-开工前确认三件事)

**练**

```bash
nvidia-smi
nvidia-smi --query-gpu=name,memory.total,compute_cap --format=csv
python3 -m sglang.launch_server --help
python3 -m sglang.launch_server --help | grep -A3 -- "--quantization"
df -h /dev/shm
nvcc --version
```

**完成判据**
- [ ] `nvidia-smi` 列出了你的 GPU，且能查到显存容量与 compute capability
- [ ] `--help` 能列出 `--tp-size`、`--pp-size` 等参数（**记下你的 SGLang 版本**）
- [ ] 你能指出**你那个版本**里对应 NVFP4 的 `--quantization` 取值——**不是 `nvfp4`**【R30】
- [ ] 你的 CUDA 是 **13.x**（当前版本已不发布 CUDA 12 镜像）【R31】
- [ ] 容器环境下 `/dev/shm` 不是默认小值【S16】
- [ ] 你能明确回答："我的集群是几个节点？每节点几张卡？"

---

### 阶段 1 · 建立定位（这份方案在解决什么）

**读** → [01 · 定位与背景](01-positioning-and-background.md)

**练**（不写代码，纯口头/书面）
1. 用一句话回答："这份方案的第一问是什么？"（目标：说出"**模型塞不塞得下单卡**"）
2. 说出 20×RTX 5090 的三条关键硬件差异。
3. 复述五步主线，并说出每一步在解决什么。
4. 说出这份方案**不覆盖**的四件事。
5. 说出源文档推荐的那个模型型号，以及**外部核对后哪三处需要修正**（见 [03 · 3.3.3](03-core-functionality.md#model-choice)）。

**完成判据**
- [ ] 你能不看资料说出："先回答『模型塞不塞得下单卡』，再谈『怎么切』和『怎么起』"【S1】
- [ ] 你能解释为什么 **TP 不能跨 PCIe Switch 边界**，并说出背后的硬件事实【S2】【R6】
- [ ] 你能指出源文档里哪些内容**不在**它的覆盖范围内（容量/SLA/监控/鉴权/升级）
- [ ] 你能说出源文档的 GSM8K 数字**该怎么读**（是跨 202 个服务配置格子的区间，不是模型能力分）【R1】

---

### 阶段 2 · 吃透并行与冷启动（本课程的技术核心）

**读** → [02 · 核心概念](02-core-concepts.md)

**练**
1. 不看资料，画出 TP / PP / DP 三种并行的**通信发生位置**。
2. 用自己的话解释："为什么 PP 跨节点比 TP 跨节点便宜？"
3. 把冷启动拆成三段成本，并指出 R-Fork 与 NVIDIA Snapshot 各解决哪一段。
4. 解释 `--mem-fraction-static` 与容器 `--shm-size` 分别治什么病。

**完成判据**
- [ ] 你能说出：TP 每层都要 All-Reduce、PP 只在 stage 边界通信、DP 完全不通信【S2】【S4】【S5】
- [ ] 你能画出冷启动三段成本表，并说清 R-Fork 只解决第 ① 段【S17】【S21】
- [ ] 你能解释为什么"精度决定装不装得下"，并给出 BF16/FP8/NVFP4 的每参数字节数量级
- [ ] 你能区分"显存不足"与"共享内存不足"这两类故障

---

### 阶段 3 · 走一遍五步部署（纸上流程）

**读** → [03 · 核心功能](03-core-functionality.md)

**练**
1. 拿到你的实际拓扑信息（`nvidia-smi topo -m` 的输出），写出你的 `--tp-size` 与 `--pp-size`。
2. 写下你的模型在所选量化格式下的单卡显存估算，判断走情况 A 还是 B。
3. 列出你的启动命令，并**逐个参数标注理由**。
4. 找出你**会踩的三个坑**（从 [04 · 4.8](04-usage.md#48-三类最常见的启动故障) 里挑）。

**完成判据**
- [ ] 你的 `--tp-size` 来自**你实测的 PCIe 域**，不是抄来的数字【S2】
- [ ] 你能说出每个分支的参数组合，并解释为什么不是别的组合【S5】【S7】
- [ ] 你的命令里包含全部 Blackwell 必配项【S11】【S12】【S15】【S16】
- [ ] 你能指出**至少一条**源文档没覆盖、但你会遇到的情况（例如 `tp × pp = 20` 不整除）

---

### 阶段 4 · 实操：启动你的第一组副本

**读** → [04 · 4.4 / 4.5](04-usage.md#case-a-command)

**练**
1. 先起**一个**副本，确认能起来、能接受请求。
2. 再按分支铺开全部副本（情况 A 的 20 个，或情况 B 的 5 个节点）。
3. 故意把 `--shm-size` 调小，观察故障表现——**建立"卡住"的直觉**【S16】。
4. **在 2 张卡上先做一次 TP**，并观察不设 `NCCL_P2P_DISABLE=1` 时是否挂起——这是 20 卡无 NVLink 集群最容易踩的坑【R33】。

**完成判据**
- [ ] 单副本起来并能响应请求
- [ ] 全部副本就绪，`nvidia-smi` 显示显存按预期占用
- [ ] 你**亲眼见过**共享内存不足时的失败表现，并知道它和显存不足长得不一样
- [ ] 你能说出这次启动的瓶颈在哪一段（权重加载 / 图编译 / 上线）

---

### 阶段 5 · 实操：接上冷启动与路由

**读** → [04 · 4.6 / 4.7](04-usage.md#step-4-cold-start)

**练**
1. 起一个 Seed 实例，再用 Client 实例从它拉权重，对比两次启动耗时。
2. 搭一个 Router，把请求分发到多个副本。
3. 测一次"杀掉一个副本 → Router 把流量挪走"。

**完成判据**
- [ ] 你能说出 R-Fork 省下的是冷启动的**哪一段**【S17】【R23】
- [ ] 你能区分"**恢复**"与"**扩容**"两种需求，并说明为什么快照只帮前者【S21】【S22】
- [ ] 你能说出 R-Fork 的**两条硬约束**：Seed 与 Client 的**并行策略必须一致**；`nccl` 后端**还需要** `--remote-instance-weight-loader-send-weights-group-ports`【R25】
- [ ] 你的 Router 能在某个副本异常时把流量挪走
- [ ] 你能说出当前路由层叫什么（`sgl-router`），以及它把请求分发到什么粒度（**完整实例**，不是 PP stage 组）【R11】【R15】
- [ ] 你能说出：为什么源文档主张"冷启动弹性不应依赖 Ray/K8s 的默认调度"【S24】，**以及这句话为什么是作者主张而不是官方建议**【R18】

---

### 阶段 6 · 判断与下一步

**读** → [05 · 相关工具](05-related-tools.md)

**练**
1. 用分层模型（引擎层 / 路由层 / 编排层 / 弹性层）给源文档提到的每个工具定位。
2. 回答："如果这套集群明天换成有 NVLink 的卡，哪几条决策会变？"
3. 回答："如果模型换成 3 倍大，情况 A / B 的分叉点会怎么移动？"
4. 回答："[05 · 5.7](05-related-tools.md#57-三条最实质的落差) 列的三条落差，分别会让你的方案改动多少？"

**完成判据**
- [ ] 你能不看资料说出 sgl-router、Ray Serve、NVIDIA Snapshot、KServe **各自在哪一层**【S23】【S24】【S21】【S22】
- [ ] 你能指出这套方案里**最脆弱的假设**（提示：拓扑、模型规格、冷启动路径三者都依赖"事前假设"）
- [ ] 你能复述**三条最实质的落差**，并说明各自会让方案怎么改【R20】【R25】【R11】【R15】
- [ ] 你能指出下一步该深挖的方向（见 [6.3](#63-实践清单)）

## 6.3 实践清单

如果想在学习之外做点东西，下面三件事按性价比排序：

| # | 项目 | 产出 | 用到哪些章节 |
|---|---|---|---|
| **1** | **拓扑 → 并行策略的决策脚本** | 输入 `nvidia-smi topo -m` 的输出，输出建议的 `--tp-size` / `--pp-size`，并在不整除时给出多种分配方案 | [04 · 4.1](04-usage.md#step-1-topology) · [03 · 3.3.2](03-core-functionality.md#step-2-grading) |
| **2** | **冷启动耗时的分解测量** | 分别测量"权重加载 / 图编译 / 首次请求"三段耗时，验证 [02 · 2.4](02-core-concepts.md#cold-start-costs) 的三段划分在**你的模型上**成立 | [02 · 2.4](02-core-concepts.md#cold-start-costs) · [04 · 4.6](04-usage.md#step-4-cold-start) |
| **3** | **单卡可行性的快速估算器** | 输入模型参数量与量化格式，输出单卡显存估算与并发空间估算 | [03 · 3.3.3](03-core-functionality.md#model-choice) · [02 · 2.2](02-core-concepts.md#precision) |

> **第 2 个项目价值最高**，因为它把本课程的概念框架变成**你自己的测量数据**——而且能直接暴露"R-Fork 到底省了多少"。

## 6.4 分层学习地图

学完之后，如果你想继续深入，按这条路线走：

```
                    ┌─────────────────────────────┐
                    │  量化与内核                 │
                    │  NVFP4 / FP8 / FlashInfer   │
                    └──────────────┬──────────────┘
                                   │ 怎么算得更快
                    ┌──────────────▼──────────────┐
                    │  推理引擎                   │
                    │  ★ SGLang（本课程）         │
                    │    vLLM / TensorRT-LLM      │
                    └──────────────┬──────────────┘
                                   │ 怎么分发
                    ┌──────────────▼──────────────┐
                    │  路由层                     │
                    │  ★ sgl-router（源文档写作     │
                    │    "SGLang Router"）         │
                    └──────────────┬──────────────┘
                                   │ 怎么编排
                    ┌──────────────▼──────────────┐
                    │  编排层                     │
                    │  Ray Serve / KServe / K8s   │
                    └──────────────┬──────────────┘
                                   │ 怎么秒级恢复
                    ┌──────────────▼──────────────┐
                    │  弹性层                     │
                    │  ★ NVIDIA Snapshot          │
                    └─────────────────────────────┘
```

**★ 标记的是本课程覆盖的部分**。往上走一层（编排层）需要的知识密度会明显上升——**建议先把上面 7 个阶段走完，再往上爬**。

## 本节小结

- **前置**：Linux + GPU 环境是必备；并行与量化的概念是理解本课程的关键前提。
- **七个阶段**：确认环境 → 建立定位 → 吃透概念 → 纸上流程 → 启动副本 → 接冷启动与路由 → 判断下一步。
- **每个阶段都有可观察的判据**——判据是"能跑出一条命令 / 能说出一句话 / 能做出一个决定"，不是"理解了"。
- **最有价值的实践是项目 2**（冷启动耗时分解测量）：它把概念变成你自己的数据。
- 想继续深入，按 [6.4](#64-分层学习地图) 的分层路线走，别跳层。
